Программно-аппаратный комплекс для автоматического тестирования элементов СКУД

Комплекс состоит  из:
аппаратные средства
	Конвертеры  Z-397 Web, далее по тексту Конвертер
	Контроллеры Z-5R Net с прошивкой Modbus, далее по тексту Контроллер
Программное обеспечение
	Много серверное веб приложение, далее по тексту Сервер
	Клиентские веб страницы, далее по тексту Страница
Тестируемое оборудование, далее по тексту Оборудование, подключается к Контроллерам.
Контроллеры имеют Входы и Выходы. Выходами Сервер выдает тестовые воздействия на Оборудование,
а Входами  сервер получает реакцию Оборудования.
Результатом теста является лог событий в форме Время, Название (воздействия или реакции), значения.
Полученный лог сравнивается с эталоном (который был записан ранее) по:
- порядку следования событий order
- времени событий от начала теста  с указанным значением погрешности в мили секундах. time

Из Контроллеров собирается Стенд тестирования.
На сервере создается папка sdands,  в ней для каждого Стенда создается своя папка c названием Стенда.
В ней хранятся:
-  файл с JSON строкой объекта Стенд 
	Свойства объекта Стенд. 
	name;name,
	description:description,
	controllers:[{}] массив объектов Контроллер (содержит информацию о контроллере),
	alias:{{}}объект объектов,  содержит соответствие названий сигналов и триггеров каждого контроллера специфическим названиям стенда
	wiring:{}  объект с названием, описанием, ссылкой на схему внутренних соединений стенда
- вложенные папки groups по их названиям
В ней хранятся:
-  файл с JSON строкой объекта Группа 
	Свойства объекта Группа. 
	name;name,
	description:description,
	wiring_group:{}  объект с названием, описанием, ссылкой на схему подключения проверяемого оборудования к контактам стенда
	triggers:[{}] массив объектов Триггер,  название и параметры (используемые триггеры в проверках)
	checks:[{}]   массив объектов Проверок 
	result:щиъект результата тестирования {order: ok/no ok, time: ok/no ok}
- вложенные папки checks по их названиям
В ней хранятся:
-  файлы с JSON строкой объекта Проверка 
	Свойства объекта Проверка. 
	name;name,
	description:description,
	initial_state:[{}] массив объектов Управляющих воздействий приводящих Контроллеры в необходимое исходное состояние перед началом тестирования. {commamd, data},  Важно! тут используются команды алиасы стенда!
	tests:[{}]   массив объектов Тест
- папка tests 
В ней хранятся:
-  файлы с JSON строкой объекта Тест 
	Свойства объекта Тест. 
	name;name,
	description:description,
	difference: допустимое различие времени события в миллисекундах
	commands:[{}]   массив объектов Управляющих воздействий с указанием времени его выполнения  и его параметров {time, commamd, data},  Важно! тут используются команды алиасы стенда!
	log:[[]] массив массивов,  Время, Название (воздействия или реакции), значения.  [time, name, data] - текущий лог
	standart:[[]] массив массивов,  Время, Название (воздействия или реакции), значения.  [time, name, data] - эталон
	result:результат сравнения лога с эталоном по двум методам {order: ok/no ok, time: ok/no ok}


Алиасы используются только для отображения на страницах как при выборе/показе команд так и лога событий. 
Фактически работа идет к командах api Сервера. 
Важно! В стенде может быть несколько контроллеров, алиас подменяет собой не только название но и выбор контроллера.
Схемы  это файлы изображений (например, .png, .jpg, pdf),
Эталон это  текущий log теста сохранённый  как standart в файле теста, 
Сравнение происходит автоматически после завершения теста,  
Результат сравнения (order: ok/no ok, time: ok/no ok) записывается в объект
 Группа и в объект Тест,  Если есть расхождения они подсвечивают красным отличия (названия и/или время) 
в окне показа текущего лога событий (текущего теста). 
Триггеры выбираемые при настройке Группы  - это те же самые триггеры, что используются в контроллерах. 
Установка исходного состояния в Проверке выполняется один раз перед запуском всей проверки, но у каждой проверки она своя.

Порядок заполнения Групп, Проверок и Тестов
При создании Группы выбирается Стенд,   Происходит наследование, это означает, что для группы однозначно пределен список алиасов. (наследуется от Стенда), 
При создании Проверки выбирается Группа,   Происходит наследование, это означает, что для проверки однозначно пределен список алиасов  и триггеров (наследуется от Группы),  
При создании Тестов выбирается Проверка,   Происходит наследование, это означает, что для проверки однозначно пределен список алиасов  и триггеров (наследуется от Проверки),
